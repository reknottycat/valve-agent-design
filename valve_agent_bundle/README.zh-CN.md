# AI 阀门设计任务编排附件 v0.1

这是与 Word 方案配套的框架无关配置草案，不是已部署的 Agent 团队、CAD 插件或调度引擎。当前没有收到真实阀门图纸，不能直接启动实际设计。

## 文件
- tasks.json：43 个任务模板、硬依赖、角色、资源池、执行动作、输出和完成条件。
- policy.yaml：边界、并发、重试、变更与发布规则；所有示例预算需项目确认。
- task_card_example.yaml：单个 CFD 工况的下发示例。占位符必须在启动前解析。
- task_card.schema.json：运行时任务卡的 JSON Schema 草案。
- validate_manifest.py：仅用 Python 标准库检查静态任务图，不会启动任何 CAD/CAE。
- sources.json：本方案核对的公开原始来源。

## 自检
运行：python validate_manifest.py
脚本检查节点、依赖、角色、资源池、工作区与无环性；输出的层次不是实际执行波次，更不代表层间必须全局等待。

## 编排引擎需要实现
1. 读取真实输入并绑定资产 URI、SHA256、单位、版本与来源。
2. 只有依赖有效、条件已解析、必需输入齐备、权限允许且资源足够才派发。
3. T33/T34 的 null 为待定；仅显式不适用时生成 WAIVED_WITH_REASON 记录。
4. T36 输出 ITERATE / FREEZE / HOLD。ITERATE 走 T37 生成下一轮；FREEZE 走 T38 及图纸交付；HOLD 输出阻塞报告，不沿冻结分支前进。
5. 条件不成立的 T37 或 T38 及其专属后继不启动。不要把“任务执行成功”等同于“工程要求通过”。
6. T28/T29/T26/T31 的 fanout 是运行时展开规则；每个子任务必须有独立目录和完整资源配额。
7. 发布产物前执行确定性校验；事实与图纸版本只能由受控集成者合并。
8. 动态变更必须比较输入哈希并只失效真正消费者；不得依赖文件时间或聊天摘要。

## 必须注意
- 当前所有真实工程参数、标准正文规则、数值验收阈值及本机适配器状态尚未填入。
- 工具成功、数值可信、需求达标、物理实测验证是不同层级。
- 最终交付级别至多为 DESIGN_REVIEW_READY；不自动执行制造放行。
- 方案只覆盖设计域，不包含采购、加工、生产排程、销售或实物试验执行。

## 启动守卫与模板绑定
`tasks.json` 中 `depends_on` 只描述有向依赖；`start_guards` 进一步描述运行结果条件。例如 T28/T29 必须等到试算数值可信，而不只是求解器退出成功。守卫中的路径为引擎需实现的版本化事实契约，不得直接交给 eval 执行。

`task_card_example.yaml` 与运行时 schema 使用相同字段，但包含未解析占位符，因此应在绑定前校验失败。编排器先绑定真实 URI、文件哈希、数值资源配额和授权条件，再用 schema 检查；还要另行检查占位符完全消除、路径位于授权工作区、资产可读取和版本正确。schema 验证不替代权限、语义或工程校验。

本附件已检查 JSON/YAML 可解析、43 节点无环，以及校验器对循环依赖、缺失依赖、工作区越界的拒绝行为。测试没有启动任何模型、CAD 或 CAE 作业，也没有验证工程参数和软件适配器。
