## 一句话定位

把**标准正文**变成**可复用的公式条目、数据表条目、参数条目**，再用**本体（ontology）**
把这三类对象对齐成一张可跨标准查询的网。**它不替代标准正文，只做复用与对齐。**

覆盖三族：**GB/T（国标）· ASME（美标）· ГОСТ（俄标）**。

## 📐 第五节：没有标准的场景（超低温 / 超高压）

> 用户原话：*"超低温的话它没有一个很明确的标准，那怎么办？那我就只能说是按照历史的经验，
> 或者说按照公式去计算去模拟……你可能超高压的、超底超低温，可能它就没有标准。
> 那没有这个标准的话，我就需要去通过现有的知识去构建。"*

这正是本库**下一版该建的东西**。先说清现状。

### 现有机制**能**承载什么

| 机制 | 怎么用 | 边界 |
|---|---|---|
| `body_status: DERIVED_NO_TEXT` | 明确标注「**非标准条款 / 自行推导，本机无对应标准正文**」 | 只解决"标出来"，不解决"记下来怎么推的" |
| 证据等级 **E0** | 「工具能运行」—— 推导结论的**起点**，永不为 E2 | 推导只能自证自洽，不能自证物理正确 |
| `kb/candidates/` | 抽取到的线索先进候选池，`confidence: LOW`，复核后才升级 | 候选 ≠ 结论 |
| 本体层 `Quantity` | 跨标准锚点：超低温用的仍是「壁厚」「许用应力」「密封比压」这几个**同一批物理量** | 只对齐，不推导 |
| 本体层 `CONFUSABLE` | 已知标准间差异的**边界**（CE 0.45 vs 0.50） | 差异是已知的，**外推不是** |
| `open_questions` 段 | 疑似同族但证据不足的量**显式登记**，不静默合并 | 登记 ≠ 解答 |
| 校验器 INV-10 | **本体不产生新事实** → 外推伪装成标准条款会被抓出来 | 这条护栏在推导层同样要建 |

### 现有机制**不能**承载什么（= 下一版要建的）

| 缺什么 | 后果 | 建议怎么建 |
|---|---|---|
| **没有推导条目层** | 推导结论只能塞进 `candidates/` 或 `usage.where` 自由文本 | 新增 `kb/derived/`，与三层并列 |
| **没有"推导链"记录** | 记不住"这个结论是从哪几条标准外推来的" | 条目带 `推导步骤[]` + `外推依据(entry_ids[])`，**必须指回本库已核条目** |
| **没有"假设集"字段** | 假设和结论混在一起，改一个假设不知道哪些结论要重算 | 条目开头列 `假设集[]`，每条假设带自己的适用范围与失效条件 |
| **没有"适用区间"字段** | 说不清"这条推导在哪个温度/压力区间内有效" | 借用本体 `Context`：`X:<KIND>:<SLUG>` 表达温度区间、压力区间、材料牌号 |
| **没有"外推距离"标记** | 从 BPVC-I（常温碳钢）外推到低温奥氏体不锈钢，读者看不出跳了几步 | 外推步骤带 `extrapolation_distance: ADJACENT \| FAR`，**FAR 必须写理由** |
| **校验器没有对应强制项** | 推导层建了也没护栏 | 推导条目：外推依据必须存在且可回溯；`FAR` 外推必须写理由；推导结论**不得**标 E2 及以上 |

### 建议的条目形状（**规划，尚未实现**）

```
kb/derived/D-<DOMAIN>-<NNN>.json
{
  "id": "D-TEST-001",
  "title_zh": "低温工况下阀座密封比压的选取（无标准覆盖）",
  "assumptions": [                 # 假设集：可独立失效
    { "id": "A1", "statement": "承压件为奥氏体不锈钢且未发生低温脆性转变",
      "valid_range": "T >= -196 C", "invalid_when": "..." }
  ],
  "derivation": [                 # 推导链：每步都要指回依据
    { "step": 1, "expr": "...",
      "from_entry_ids": ["P-MAT-001", "P-TEST-014"],   # 必须是本库已核条目
      "extrapolation_distance": "ADJACENT",
      "rationale": "..." }
  ],
  "applicability": { "valid_when": "...", "not_valid_when": "..." },
  "evidence": { "grade": "E0", "status": "DERIVED" },
  "source": { "body_status": "DERIVED_NO_TEXT" }
}
```

**三条纪律**：

1. **推导层永远不是标准条款**。`body_status` 必须是 `DERIVED_NO_TEXT`，
   `status` 不能是 `VERIFIED_CLAUSE`，**证据等级上限 E1**。
2. **每个推导必须指回本库已核条目**。指不回去 = 这是新知识，应该去抓标准，不该进推导层。
3. **不确定就登记**。不设范围、说不清适用区间的，先进本体 `open_questions`，不硬写推导。

> **这一节是本文件里唯一的"规划"内容**。其余都是已落盘、已复算的状态。
> 推导层的实际落地顺序建议：先做 `assumptions` + `derivation` 两个字段的 schema，
> 再做校验器（外推依据可回溯 + E 级上限 + FAR 理由必填），最后才开条目。
