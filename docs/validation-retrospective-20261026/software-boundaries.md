# 软件限制、数值限制与商业后端比较边界

## 四类问题不能混写

| 类别 | 已证实例 | 软件替换可能改善什么 | 替换不能自动证明什么 |
|---|---|---|---|
| 自建代码/集成缺陷 | BC无value解析、FPE横幅误杀、monitor内存、CPU继承、C++ API/fixture错误 | 集成产品可能减少自建胶水代码、维护和兼容成本 | 不能从这些错误推定OpenFOAM本体全部有bug；修复也不等物理正确 |
| 工具链/功能与接口边界 | 精确版本字段/矩阵类型/relax调用不同；STEP只保几何、未验证原生特征树；局部重网格选项行为不符假设 | 成熟几何修复、网格工作流、GUI诊断、统一后处理或厂商支持可能更省工 | 不保证保留参数历史，不保证给定CAD/网格自动合格；需实际测试 |
| 数值收敛/离散问题 | 质量Failed3、制造解联合门未过、外层ΔP/ΔU反弹、内层残差和原方程不平衡不同 | 可比较网格策略、离散、耦合和诊断实现 | 无一产品名称能代替收敛/守恒/敏感性证据；现有数据未定位为OpenFOAM算法bug |
| 物理建模/工程证据 | F80人工封口、固定开度、研究物性、材料/接触/泄漏/额定工况未核 | 更方便建立/检查模型和组织验证 | 商业求解器不会补齐真实边界、许用值、标准适用性或样机试验 |

## 可以做的商业后端小对照（建议，未执行/未购买）

官方 Fluent 文档确有 [watertight / fault-tolerant guided meshing 工作流](https://ansyshelp.ansys.com/public/Views/Secured/corp/v242/en/flu_ug/tgd_user_workflow_guided_intro.html)。这说明可考察其 CAD/网格工作流，不证明本项目模型一定能成功，也不证明当前许可已包含相应功能。

官方 [Fluent 收敛监控说明](https://ansyshelp.ansys.com/public/Views/Secured/corp/v251/en/flu_ug/flu_ug_sec_solve_monitor.html) 包含残差及力、面积/体积分监控与归一化说明。跨求解器不能直接拿归一化残差数值排名；应比较同定义的有量纲守恒、端口量和持续稳定性。

[COMSOL 对制造解验证的说明](https://www.comsol.com/blogs/verify-simulations-with-the-method-of-manufactured-solutions)区分数学/数值验证与针对现实的验证。两求解器一致也不是实物验证。

建议只在**用户已有许可且明确授权的后端**做一个可停止的同输入试验：

1. 固定CAD hash、DN200、57 mm固定研究位移、流体物性、Re、边界及压力参考/取压截面；把F80处理写清。仍使用人工封口则两边均只能称研究。
2. 记录网格质量/单元类型/分辨率与近壁策略差异；网格不一致时不得称“纯求解器A/B”。几何修复若改源形状须另版本与差异说明。
3. 比较建模人时、自动化接口、失败恢复、真实可读输出、守恒、端口Q/ΔP及固定窗口；预先定义通过条件、预算与停止条件。
4. 研究结果达标后仍须网格/格式敏感性、物理输入审查、标准和独立复核；额定性能/制造放行有独立门。
5. 只有这个小对照证明工程收益后，再决定采购或迁移。不因当前疲劳或“商业”标签直接决定全面重写。

## 保留的架构资产

保留认知编排、标准/公式本体、来源manifest、版本/单位治理、错误记录、验收分层、数据驱动计算书。将CAD/网格/求解作为可替换的专业后端适配器，而不是把原工作全丢弃。当前开源链能运行和产出研究证据已被证明；短板是端到端工程成熟度及维护成本，尚无足够证据评价商业路线的实际收益。

## 当前不能做出的承诺

没有完成商业软件安装/许可核验、同CAD导入、同工况求解或特征树往返。不把商业官方文档当本项目实测。不承诺“换软件就能收敛”、不把所有原理/模型问题归软件、不据此自动购买或运行。

## 路线复盘：哪些应保留，哪些应停止重复

**回顾性判断（不是数值根因证明）：在尚未建立成熟后端的同输入参考基线前，持续投入自建观察器、监督器、解析器和求解器内部探针，已明显增加集成维护与定位成本。** 这些工作产生了可复用诊断资产，但未同步换来整阀性能验收闭合；继续沿原方向无限深化，存在机会成本。这不等于这些诊断没有价值，也不证明 OpenFOAM 无能力。

- **保留：**现有CAD/STEP与BOM、固定R1、输入/输出hash、标准与公式来源、真实失败及成功对照、代表域里程碑、可替换后端契约。
- **停止重复：**重跑已达门的time960代表域；没有新因果假设的盲目加密/扫relTol；把默认MeshOK或线性残差当全验收；为了得到一个绿色状态事后改门；继续大场分片进入Git；把解析器/守卫错误当流动发散。
- **先做决策证据：**选一个已有许可的成熟后端，在同CAD/同研究边界上检验导入、网格、守恒、可观察性、自动化和复现成本。若建模/诊断负担显著减少且不牺牲证据链，再安排适配；若仅UI不同或仍受同一人工边界/不收敛限制，不据此全面迁移。
- **无论后端：**人工F80和实际材料/密封/额定输入欠项仍单列，不能把它们当换软件已解决。
